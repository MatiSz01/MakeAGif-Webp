# MakeAGIF v3.1.5 — Plan de optimización de rendimiento

Documento de referencia para continuar el trabajo.  
**Base de código:** `MakeAGIF_v3.1.4_DND_Prototype.py`  
**Objetivo:** mejorar responsividad de UI y tiempo de export **sin regresar precisión frame-exact** (IN/OUT, scene cuts, overlay en pausa).

---

## Principios de la versión

1. **Frame-exact es sagrado** — cambios de seek/scale solo donde el usuario no exporta (scrub) o con flag explícito.
2. **UI nunca espera ffmpeg** — todo decode/thumb en worker.
3. **Menos procesos** — un ffprobe por import; menos spawns en preview.
4. **Export: medir antes de reescribir** — pipe ffmpeg→gifski al final, con fallback al pipeline PNG actual.

---

## Diagnóstico (v3.1.4) — dónde se va el tiempo

Casi todo pasa por **ffmpeg/ffprobe**. Cuellos principales:

| Área | Problema | Impacto |
|------|----------|---------|
| **Export** | PNG intermedios en disco → gifski/IM/WebP | Alto I/O, clips largos |
| **Export** | `-ss` antes de `-i` + decode hasta IN exacto | Muy lento con IN lejano |
| **Export** | Modo ITERATIVE = N × (extracción + encode) | Multiplicador más grande |
| **Import** | `get_video_specs`: hasta 3 procesos (ffmpeg -i + 2× ffprobe) | ~3× costo por archivo |
| **Trimmer preview** | 1 proceso ffmpeg por frame; thumbs IN/OUT **sync en UI** | Scrub lento; freezes |
| **Trim previews panel** | 2× `extract_frame_at` sync al editar IN/OUT | Micro-freeze |
| **Scene detect** | Decode completo siempre; cache **borrada al startup** | Re-DETECT cada sesión |
| **Proxy ½** | Transcode completo del source (no parcial IN–OUT) | Costo alto en sources largos |
| **Batch export** | 1 worker secuencial | Colas grandes lentas |

### Lo que ya está bien (no romper)

- Import async (`TaskAnalyzerWorker`)
- Preview trimmer async + coalesce + `_preview_gen`
- Caché extracción PNG export (`CACHE_VER`, knowledge cache, Tier-1)
- Proxy reutilizable por content key
- `_authoritative_playhead_ms` / playhead lógico vs Qt
- Presets en `_bundle_root()` / `presets/` junto al ejecutable

## Fase 0 — Baseline (antes de codear)

Clips de prueba:

| Clip | Uso |
|------|-----|
| Vertical 1080×1620 @ 23.976, ~30s | Trim + scrub + export |
| Largo (>5 min) con IN lejano | Seek extracción |
| Batch 5 archivos | Import paralelo |
| Mismo clip ITERATIVE 16 MB | Warm-start / re-run |

Métricas a anotar:

- Tiempo abrir trimmer → primer frame visible
- Tiempo scrub 10 frames (promedio)
- Tiempo SET IN + SET OUT (freeze UI)
- Tiempo import (1 archivo)
- Tiempo export MANUAL + ITERATIVE (1er run vs cache hit)
- Nº procesos ffmpeg durante scrub

## PRs planificados

### PR 1 — UI async: thumbs y trim previews (P0)

**Alcance:** sacar del hilo principal las llamadas síncronas a `extract_frame_at`.

**Zonas:**

- `TrimDialog._update_trim_thumb`
- `DropZoneWidget.update_trim_previews`
- `MainWindow._update_batch_trim_previews` / `_refresh_trim_previews`

**Implementación:**

- Patrón trimmer: worker + Signal bridge + coalesce `(path, fi, tw, th)`
- Debounce 150–250 ms en `_refresh_trim_previews`
- Cancel con generation counter (como `_preview_gen`)

**Aceptación:**

- SET IN/OUT no congela UI de forma perceptible
- Thumbs tras editar trim ≤ ~500 ms
- Mismo frame index que trimmer/export

**Riesgo:** bajo

---

### PR 2 — Import: un solo ffprobe (P0)

**Alcance:** fusionar `ffmpeg -i` + `_probe_vfr` + `_probe_stream_frame_stats`.

**Enfoque:**

```text
ffprobe -v error -select_streams v:0
  -show_entries stream=width,height,r_frame_rate,avg_frame_rate,nb_frames,duration
  -show_entries format=duration
  -of json
```

- Misma estructura `specs` que hoy
- Timeout 10s, fallback silencioso
- `Task.__init__` sync: deprecar o specs vacíos (solo `TaskAnalyzerWorker`)

**Aceptación:** mismos specs vs v3.1.4; import ~2× más rápido

**Riesgo:** bajo-medio (banner VFR)

---

### PR 3 — Preview scrub: menos ffmpeg (P1)

**Alcance:** overlay trimmer; **no** export.

1. Scrub → `exact=False` + `fast_bilinear`; park/I/O → `exact=True` + lanczos
2. Coalesce 50–75 ms en drag; click → decode exacto inmediato
3. Prefetch `fi±1` en idle (baja prioridad, cancelable)
4. LRU 48 → 96 `(fi, exact)` — medir RAM

**Opcional:** caché disco `%TEMP%\gif_tool_frame_preview\{content_key}\`

**Aceptación:** scrub ≥30% más rápido; frame pausado idéntico al export

**Riesgo:** bajo-medio

---

### PR 4 — Scene cache: persistir entre sesiones (P1)

**Hoy:** `clear_scene_cache_on_app_startup()` borra todo cada launch.

**v3.1.5:**

- Default: **no** borrar al startup
- CLEAR CACHE manual sigue igual
- Advanced: checkbox “Clear scene cache on startup” (default OFF)

**Riesgo:** bajo (producto)

---

### PR 5 — Export: seek más barato con IN lejano (P2)

**Alcance:** acelerar extracción PNG; **mismos frames**.

- Probar `-ss` output-side / doble seek cuando `in_sec > ~30s`
- Mantener verificación `expected_frames` / log Trim verify
- **`CACHE_VER` → v8** solo si cambia conteo en suite de prueba

**Aceptación:** IN a 2 min ≥25% más rápido; verify OK en 23.976 / 29.97 / 30 fps

**Riesgo:** alto — QA obligatorio

---

### PR 6 — Export sin PNG intermedios (P2, opcional)

**Flag Advanced:** “Fast export (experimental)”.

- GIF: pipe decode → gifski (fallback PNG actual)
- WebP sin alpha: ffmpeg directo
- Alpha WebP: pipeline actual hasta v3.1.6

**Riesgo:** alto → v3.1.5-beta o v3.1.6

---

### PR 7 — Batch export paralelo (P4, opcional)

- `max_workers=2` configurable
- Default secuencial
- **Recomendación:** v3.1.6
